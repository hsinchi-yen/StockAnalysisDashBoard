# 效能基準

以 2330、3 年期間，用真實瀏覽器（Chrome headless，1280×900）與真實 FinMind 資料量測。
「舊版」是 commit `8fdef8e`，從外部加上 FinMind 呼叫計數，其餘未改。兩版使用同一顆 Sponsor
token、同一台開發機，都從空快取開始。

冷查詢＝快取全空，熱查詢＝同一天再查一次。

## 開發機

| 指標 | 舊版 | 新版 | 變化 |
|---|---|---|---|
| 冷查詢 FinMind 呼叫數 | 45 | 13 | −71% |
| 冷查詢全部完成 | 26.67 秒 | 10.37 秒 | −61% |
| 冷查詢 `buy_score` | 約 22 秒 | 8.13 秒 | −63% |
| 冷查詢首屏 | 2.91 秒（只有股價） | 2.90 秒（完整階梯圖） | 持平 |
| 熱查詢首屏 | 1.20 秒 | 0.30 秒 | −75% |
| 熱查詢全部完成 | 1.21 秒 | 0.39 秒 | −68% |
| 熱查詢 FinMind 呼叫數 | 1 | 0 | |
| 首屏繪製的 Plotly 圖表 | 17 張 | 1 張 | −94% |

**首屏目標（↓ 40%）只有熱查詢達成。** 冷查詢的第一屏要等估值所需的 FinMind 資料，時間與舊版相同，
但舊版這時只顯示股價，新版已是完整的風險/獲利階梯圖。

新版比舊版多 2 個請求（`quick_summary`、`margin_trading`）。

## 量測注意事項

- 網站 session JWT 會被 FinMind 拒絕（`Token is illegal`），程式改走匿名。同一支舊版在這種 token 下量到
  86 次呼叫，因為每個 dataset 都先失敗一次。新版會記住被拒的 token。
- 匿名配額由對外 IP 共用，用完時端點會回 502，這時的數字不能當基準。
- Goodinfo 對開發機 IP 回 403。舊版每次重試約 15 秒，是 `buy_score`、`foreign_holding`、`shareholding`
  變慢的主因。若 Goodinfo 未封鎖，舊版的冷查詢會快一些，兩版差距也會縮小。
- 未量測 Android WebView。
